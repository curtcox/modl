Diagram definition language full documentation and examples

# starts a comment. Inline comments are supported.
Node line: n [size] [shape] [color] [url] [text...]
Edge line: a -> b (-> c ...) [size] [lineStyle] [color] [url] [text...]
Attribute order is fixed: size, style, color, URL fragment, text — but any can be omitted.
Quote an id or text with "…" or '…' to take it literally: "v1.2" square "Input -> Output #1". Quoted words are never keywords or URLs.
URL token: /example.com becomes https://example.com. You can also use https://... directly.
A node whose URL is an image (.svg, .png, .jpg, … or any URL that loads as an image) is drawn as that image. A size fits the image in that size's box; without one the image keeps its natural size. A shape draws a frame around it, and text appears below it.
A line containing only a supported color name sets the diagram background color.

          Saving on HashBin sharing & URL format

          Save to HashBin uploads the source and node positions to hashbin.org, paid from your account balance (usually $0.01). The URL becomes #<CID>, where the CID is a 256t string: a short link anyone can open; the diagram is fetched from 256t.us.
          The first save asks you to Connect: you sign in on hashbin.org and approve this editor. This browser then stays connected (renewed each time you use it, for up to 30 days idle) until you press Disconnect or remove the editor from your HashBin account. Diagrams are kept for your account's default retention.
          Saved content can't change, so editing a saved diagram switches the URL back to the long #h1= form until you save again. Saving an unchanged diagram again extends how long it's kept.
          #<CID> also opens any plain-text file on HashBin as diagram source.
          Shareable state: source + node positions are encoded in the URL hash, or saved on HashBin and referenced by CID.
          Try: edit the text, then Save to HashBin for a short link.
