Grammar reference

A compact, complete description of modl: the grammar, how a line is processed, the defaults, the error messages, and how attributes are drawn.

Grammar

In EBNF. Words are separated by runs of spaces or tabs. Reserved words are lowercase and case-sensitive. 

source       = line , { newline , line } ;
newline      = "\n" | "\r\n" ;
line         = [ statement ] , [ comment ] ;
comment      = "#" , { any character } ;
               (* only at the start of the line (after optional whitespace)
                  or directly after whitespace; a "#" inside a word is text *)

statement    = background | edge-line | node-line ;
               (* tried in this order; see "Processing a line" *)

background   = color ;                     (* the only word on the line *)

node-line    = id , node-attrs ;
node-attrs   = [ size ] , [ shape ] , [ color ] , [ url ] , [ text ] ;

edge-line    = segment , "->" , segment , { "->" , segment } ;
               (* empty segments are skipped; at least two must remain *)
segment      = id , { word } ;
               (* words after the id are attributes only in the last
                  non-empty segment, and ignored in every other one *)
edge-attrs   = [ size ] , [ line-style ] , [ color ] , [ url ] , [ text ] ;

id           = id-char , { id-char } ;
id-char      = "A".."Z" | "a".."z" | "0".."9" | "_" | ":" | "-" ;

size         = "tiny" | "small" | "normal" | "big" | "bigger" | "huge" ;
shape        = "none" | "circle" | "square" | "diamond" | "triangle" | "hex" ;
line-style   = "solid" | "dashed" | "dotted" | "bold" ;
color        = "gray" | "black" | "white" | "red" | "orange" | "yellow"
             | "green" | "teal" | "blue" | "purple" | "pink" | "brown" ;
url          = ( "/" | "http://" | "https://" | "www." | "mailto:" ) , { non-space } ;
text         = word , { word } ;           (* rejoined with single spaces *)
word         = non-space , { non-space } ;

Attribute slots are matched greedily, left to right, each at most once. A word that doesn't fit the current or a later slot starts the text, and the text runs to the end of the line.

Processing a line

  1. Strip the comment. If the first non-blank character is #, the line is empty. Otherwise everything from the first whitespace-then-# onward is removed.
  2. Skip blank lines.
  3. Background. If the trimmed line is exactly a color name, it becomes the background color, replacing any earlier background.
  4. Edge line. If the line contains ->:
    1. Split on ->, trim each segment, and drop empty segments. Fewer than two remaining is a malformed edge line.
    2. From each segment except the last, take the first word as an id. An invalid id is reported and left out of the chain.
    3. The first word of the last segment is the final id. If it is invalid, the error is reported and the whole line is skipped. The remaining words are parsed as edge-attrs.
    4. For each consecutive pair of ids, create a node for each id that doesn't exist yet, and add an edge with the attributes, applying defaults for missing ones.
  5. Node line. Otherwise the first word is the id (an invalid id is reported and the line skipped). The remaining words are parsed as node-attrs. The node is created if needed, then each attribute that was given replaces the node's current value. Text is replaced only when new text is given.

Lines with errors are skipped as described, and processing continues. The diagram always shows everything that parsed.

Node URLs using http(s) are also tried as images. See image nodes.

Error messages

Errors appear in the box under the source and the status reads Parse errors. Line numbers count every line, including blank and comment lines, starting at 1.

MessageCause
Line N: invalid node id "x" The first word of a node line, or an id in an edge line, contains a character other than letters, digits, _, : and -. try it
Line N: malformed edge line The line contains -> but fewer than two non-empty segments, such as a -> or -> b. try it

Everything else is valid modl. Misplaced keywords, unknown words and extra URLs never cause errors; they become label text. See Gotchas.
